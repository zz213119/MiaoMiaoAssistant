# 喵喵助手-文本改写助手 (QQMiaoAssistant)

基于 Android **无障碍服务（Accessibility Service）** 的文本改写 / 替换工具，支持 **QQ / 微信 / 抖音 / 快手 / 全局模式 / 自定义应用**。

## 项目来源

本项目最初由一个名为「QQ喵喵助手」的 APK（`base.apk.1`）**逆向拆解并重构**而来的可编译工程，本仓库在此基础上二次开发，扩展了多应用适配、微信兼容方案、界面可配置等功能。

## 功能

- **自定义文本替换规则**（`原词=替换词`，也支持 `→`，可配置多条、按顺序应用）
- **断句追加**（按标点分句，句末追加可自定义文本，默认"喵"）
- **句末随机颜文字**（内置 50+ 个，可自定义）
- **处理模式**：标点触发 / 实时处理
- **应用范围**：单独开关：QQ / 微信 / 抖音 / 快手
  - **全局模式**：对所有前台应用生效
  - **自定义模式**：自行填写包名，适配上面未列出的 App
- **调试日志**：内存缓冲区记录运行日志（不依赖系统 logcat，跨机型更可靠），设置里可一键开关，默认关闭以省电

## 微信兼容方案（重点说明）

微信的输入框存在两层特殊限制，均已在本项目中处理：

1. **不主动上报内容变化事件**：常规 App 打字会自动触发无障碍事件通知，微信不会。
   → 解决方式：加入**主动轮询**机制（每 400ms 主动查询一次当前输入框内容），不再单纯依赖被动事件通知。

2. **对第三方无障碍服务返回混淆后的假内容**（约从微信 8.0.52 版本左右开始）：即使轮询到输入框，读到的文字也是乱码，无法获取真实内容。
   → 解决方式：微信的混淆逻辑会对系统内置读屏服务（如"选择朗读"）放行，判断依据仅为**服务类名字符串匹配**。本项目注册了一个类名与系统"选择朗读"服务完全相同（`com.google.android.accessibility.selecttospeak.SelectToSpeakService`）的无障碍服务来绕过这层限制，实际逻辑仍复用同一套代码，只是"借用"了这个类名。此方案参考自社区已验证的公开方法（[ven-coder/Assists](https://github.com/ven-coder/Assists)）。

**⚠️ 需要知道的风险**：这是利用字符串匹配的灰色手段，不是官方支持的正规接口，微信未来版本随时可能改为更严格的校验（如签名校验）导致此方法失效。在系统无障碍设置列表中，该服务会显示为"选择朗读"而非本应用名称，属预期行为。

## 技术栈

- 纯 Android 原生 API（无第三方依赖）
- Java
- Gradle 8.8 / AGP 8.4.2
- minSdk 23 / compileSdk 34
- GitHub Actions 自动构建（push 到 main 分支自动触发编译，产物在 Actions 页面的 Artifacts 中下载）

## 构建

```bash
./gradlew assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

也可以直接 fork/clone 本仓库后推送到 GitHub，通过 Actions 自动编译获取 APK，无需本地环境。

## 使用

1. 安装 APK（需开启"允许未知来源安装"）
2. 打开应用 → 在"应用范围"里勾选需要生效的 App（或开启全局模式）
3. 配置替换规则 / 断句追加 / 颜文字 / 处理模式 → 保存设置
4. 开启无障碍服务（设置中会显示为"选择朗读"）
5. 在目标 App 聊天中输入文字，触发规则自动改写

## 已知限制

- 微信的兼容方案依赖字符串匹配漏洞，不保证长期有效
- 部分定制系统（如深度定制的国产 ROM）可能限制 App 读取自身 logcat，本项目已改用内存日志缓冲区规避此问题
- 每次通过 CI 编译产生的 debug 包签名可能不一致，更新安装前需先卸载旧版本，安装后需重新在系统设置中开启无障碍权限
